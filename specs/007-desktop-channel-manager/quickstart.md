# Quickstart/快速验证: Desktop Channel Manager/桌面渠道管理工具

**Feature**: [spec.md](spec.md) | **Environment**: Windows + Node.js ≥22

## 1. Start the Desktop App/启动桌面应用

```bash
npm install
npm run desktop:dev
```

- 首次启动显示首页，服务状态为“已停止”。
- 点击“启动服务”：状态进入“启动中”，随后变为“运行中”。
- 点击“停止服务”并确认：状态回到“已停止”。

## 2. Register and Test a Channel/注册并测试渠道

1. 进入“通知渠道”，点击“新增渠道”。
2. 选择渠道类型与连接方式，填写名称、凭据和接收目标。
3. 保存前核对摘要：敏感值只显示掩码。
4. 保存后状态为“未启用”，点击“发送测试消息”。
5. 在目标接收端确认收到测试消息，界面显示成功且渠道变为“已启用”。

验证失败路径：故意输入错误凭据，测试应失败且渠道保持原启用状态；修正后重新测试。

## 3. Modify a Channel/修改渠道

1. 在渠道列表选择“修改”。
2. 仅修改名称或一项凭据，敏感字段留空表示保留。
3. 保存后确认未修改字段、启用状态与更新时间符合预期。
4. 尝试输入冲突名称：保存应失败且原配置不变。

## 4. Inspect Registration/查看注册信息

1. 进入“注册信息”页面。
2. 核对 CodeBuddy、Claude Code、Codex CLI 的注册状态与最近接入信号。
3. 点击刷新：外部修改配置后状态应更新。

## 5. Verify Tray Behavior/验证托盘行为

1. 服务运行时点击最小化：窗口隐藏，托盘图标可见，服务保持运行。
2. 托盘菜单选择“打开主界面”：恢复原窗口，不出现重复窗口。
3. 托盘菜单选择“退出”：出现确认提示；取消退出后一切保持不变，确认后应用与服务停止。

## 6. Security Spot Check/安全抽查

- 渠道列表、日志、错误消息和测试结果中不出现明文凭据。
- 渲染进程无法直接访问 Node API 或本地文件。
- 使用虚构凭据执行测试；失败信息不包含完整敏感路径。

## Troubleshooting/排查

| 现象                 | 处理                                            |
| -------------------- | ----------------------------------------------- |
| 启动显示“外部运行中” | 先停止外部 `notice serve` 进程，再回到 GUI 启动 |
| 测试长时间进行中     | 等待最终超时结果，检查目标平台和网络            |
| 注册信息读取失败     | 检查对应配置文件权限；界面提示已脱敏            |
| 修改保存冲突         | 重新加载渠道数据后再保存                        |

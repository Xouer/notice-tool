# Feature Specification: Interactive Channel Setup Wizard/交互式渠道配置向导

**Feature Branch**: `003-interactive-credential-setup`

**Created**: 2026-11-07

**Status**: Draft

**Input**: User description: "我意思到用命令行输入飞书相关信息可能会有问题，需要改成交互命令行的导航的方式。选择输入类型，选择输入方式，选择输入值，一步一步提示来"

## User Scenarios & Testing/用户场景与测试

### User Story 1 - Step-by-Step Guided Feishu Configuration/分步引导式飞书配置 (Priority: P1)

作为不熟悉命令行参数的开发者，我希望运行配置命令后，工具以向导形式一步一步提示我完成飞书渠道配置：先选择"输入类型"（渠道类型），再选择"输入方式"（连接方式），再逐项输入具体值（每一步都有说明与示例），全部完成并确认后一次性保存，而不需要我记住或拼装任何命令行标志。

**Why this priority/优先级理由**: 这是本特性的核心——把"一次性命令行传参"替换为"逐步导航输入"，直接解决用户"命令行输入飞书相关信息可能出错"的痛点，是所有后续改进的前提。

**Independent Test/独立测试**: 仅实现本故事即可通过"运行配置命令 → 跟随提示逐步选择/输入 → 出现确认摘要 → 确认后保存成功并出现在渠道列表"完整验证，全程未在命令行输入任何凭据值。

**Acceptance Scenarios/验收场景**:

1. **Given** 用户运行渠道配置命令且未提供凭据类标志，**When** 向导启动，**Then** 第一步列出全部支持的渠道类型供选择（含飞书），每个选项附一句用途说明。
2. **Given** 用户选择了"飞书"渠道，**When** 进入"输入方式"步骤，**Then** 向导列出"应用凭证（推荐）"与"群机器人 Webhook"两种连接方式及其区别说明，并给出推荐默认项。
3. **Given** 用户选择了"应用凭证"方式，**When** 进入"输入值"阶段，**Then** 向导按顺序逐项提示：渠道名称、App ID、App Secret（输入不回显明文）、接收目标类型（选择：群会话/用户）、接收目标 ID；每一项都显示该字段的含义、格式示例（如 `cli_` 前缀、`oc_`/`ou_` 前缀）和获取方法提示。
4. **Given** 用户完成全部输入，**When** 向导展示确认摘要（凭据脱敏显示），**Then** 用户可以选择"确认保存""返回上一步修改"或"取消"；选择确认后配置才写入，取消则不写入任何配置。
5. **Given** 用户在某一步输入了格式不合法的值（如 App ID 为空、接收目标 ID 缺少预期前缀），**When** 用户提交该步，**Then** 向导立即指出具体错误并以人类可读的方式解释预期格式，允许当场重试，不中断整个流程。

### User Story 2 - Navigate Back, Skip and Cancel Safely/返回、跳过与安全取消 (Priority: P2)

作为使用向导的用户，我希望在任意步骤可以返回上一步修改之前的输入、可以中断/取消整个向导（已输入内容不被保存），并在被中断后重新运行向导时从头开始，以便放心地探索而不会产生半成品配置。

**Why this priority/优先级理由**: 导航体验是"向导式"区别于"问答式"的关键能力，但建立在故事 1 的分步流程之上。

**Independent Test/独立测试**: 在向导中前进一步后选择"返回上一步"修改输入、再于中途取消，验证渠道列表无新增记录，即可独立验证本故事。

**Acceptance Scenarios/验收场景**:

1. **Given** 用户已走过至少两个步骤，**When** 用户在任一步骤选择"返回上一步"，**Then** 向导回到上一步并保留该步及更早步骤的已输入值供修改。
2. **Given** 用户在任一步骤（包括凭据输入中途）选择"取消"或按中断快捷键，**When** 向导退出，**Then** 已有渠道配置保持不变，未产生任何新配置或半完整记录，工具给出已取消的明确提示。
3. **Given** 用户在"输入值"阶段跳过可选项（如渠道名称），**When** 该字段为可选项，**Then** 向导使用合理的默认值（如渠道类型 + 时间后缀）并在确认摘要中展示默认值来源。
4. **Given** 向导因终端不支持交互（如被脚本以非交互方式调用）而无法运行，**When** 工具检测到该情况，**Then** 工具提示需要交互式终端，并指引改用既有命令行标志方式（该方式保持不变）。

### User Story 3 - Wizard Covers All Channel Types Consistently/向导覆盖全部渠道类型 (Priority: P3)

作为配置钉钉、邮箱、微信、QQ 等其他渠道的用户，我希望同样的向导式分步输入也适用于这些渠道（每种渠道只出现它需要的字段），以便所有渠道的配置体验一致，不必为每种渠道学习不同的输入方法。

**Why this priority/优先级理由**: 一致性提升整体体验并避免两套配置心智，但飞书（故事 1）才是本次痛点的来源，价值递增而非必需。

**Independent Test/独立测试**: 运行向导选择任一非飞书渠道，验证仅出现该渠道所需字段并能完整走完配置，即可独立验证本故事。

**Acceptance Scenarios/验收场景**:

1. **Given** 用户选择"钉钉""邮箱""微信"或"QQ"渠道，**When** 向导进入"输入方式"与"输入值"步骤，**Then** 仅列出该渠道实际支持的连接方式与字段，不出现飞书专属字段（如 App ID）。
2. **Given** 某渠道存在多种连接方式（如微信的企业微信群机器人与 Server酱），**When** 向导进入"输入方式"步骤，**Then** 列出全部方式供选择，且后续字段随所选方式变化。
3. **Given** 用户已完成任一渠道的向导配置，**When** 用户随后运行"测试发送"命令，**Then** 测试行为与用命令行标志配置的同类渠道完全一致。

---

### Edge Cases/边界情况

- **敏感输入回显**：App Secret、SMTP 授权码等敏感值输入时必须不回显明文（不显示在屏幕），确认摘要中一律脱敏；复制粘贴含首尾空格的值时向导自动去除首尾空白后再校验。
- **输入中断**（如终端窗口被关闭、进程被杀）：与"取消"同语义，不落盘任何半成品配置。
- **重名渠道**：向导在确认摘要阶段检测到渠道名与既有渠道重复时提示冲突，要求改名或显式选择覆盖，不允许静默覆盖。
- **终端兼容性**：方向键/选择列表不可用的极简终端中，向导必须退化为数字输入（输入序号选择），不得无法操作。
- **粘贴多行内容**：用户误将多行文本粘贴进单行输入框时，向导取首行并提示确认，避免凭据被截断后静默保存。
- **非交互调用**：脚本/CI 等非交互环境调用配置命令时，向导不被触发，沿用既有命令行标志路径并给出指引（保证兼容性，见 FR-009）。
- **配置命令行为不变**：已提供完整凭据标志的既有命令行用法必须保持原行为，不弹向导。

## Requirements/需求

### Functional Requirements/功能需求

- **FR-001 向导入口**: 当用户运行渠道配置命令且未提供必填的凭据类标志时，系统必须启动交互式向导；用户也必须能通过显式标志（如 `--interactive`）强制进入向导。
- **FR-002 输入类型选择**: 向导第一步必须列出全部支持的渠道类型供用户选择，每项含简短用途说明。
- **FR-003 输入方式选择**: 选定渠道后，向导必须列出该渠道支持的连接方式（飞书：应用凭证/Webhook；其他渠道同理），含方式说明与推荐标记，后续字段随所选方式变化。
- **FR-004 逐项输入值**: 向导必须按所选类型与方式逐项提示输入值；每个字段提示必须包含：字段含义、格式示例/前缀要求、获取方法提示；敏感字段输入不得回显明文。
- **FR-005 即时校验**: 每一步提交时向导必须做该字段的格式与完整性校验，失败时给出定位到具体字段的人类可读错误并允许当场重试，不中断流程。
- **FR-006 确认摘要与写入**: 全部输入完成后，向导必须展示确认摘要（凭据脱敏），用户必须能选择"确认保存""返回上一步修改"或"取消"；只有确认后才写入配置。
- **FR-007 导航控制**: 向导必须在每一步提供"上一步"与"取消"操作；取消或中断不得产生任何配置变更；可选项跳过时使用文档化的默认值。
- **FR-008 终端兼容回退**: 交互式选择组件在能力不足的终端上必须退化为数字序号输入；检测到非交互终端时必须拒绝启动向导并给出指引。
- **FR-009 兼容性**: 既有命令行标志配置方式必须原样保留且行为不变；向导产出的渠道配置与命令行方式产出的配置在存储、测试发送、通知发送上完全等价。
- **FR-010 凭据保护**: 向导过程中收集的敏感凭据必须同等强度加密存储，不得出现在日志、错误信息或任何回显中；确认摘要与渠道列表一律脱敏。

### Key Entities/关键实体

- **向导会话/Wizard Session**: 一次配置向导运行期间的临时输入状态（已选类型、方式、各字段值与游标位置）；仅在内存中存在，随确认写入或取消丢弃，不落盘。
- **渠道配置/Channel Config**: 复用既有"通知渠道配置"实体；向导只是该实体的另一种创建/编辑入口，不新增存储结构。

## Success Criteria/成功标准

### Measurable Outcomes/可度量结果

- **SC-001**: 从未见过本工具的用户仅凭向导内提示，无需查阅文档即可完成一次飞书渠道配置，目标首次成功率不低于 90%。
- **SC-002**: 一次完整的飞书应用凭证渠道向导配置（含确认）可在 3 分钟内完成。
- **SC-003**: 向导流程中任意步骤取消或中断后，本地渠道配置记录数保持不变（无半成品数据）。
- **SC-004**: 向导产出的配置在测试发送与任务通知行为上与命令行标志方式产出完全一致（现有测试全部通过，无回归）。
- **SC-005**: 向导全过程中敏感凭据明文零出现（屏幕回显、日志、错误信息均脱敏）。

## Security & Data Protection/安全与数据保护

- **数据类型**: 向导临时收集既有渠道凭据字段（如 App Secret、Webhook URL、SMTP 授权码等）；不新增数据类型。
- **访问主体**: 仅本机用户本人；凭据仅用于建立通知渠道连接。
- **授权模型**: 无新增权限；沿用各渠道既有授权方式。
- **脱敏与存储**: 敏感输入不回显明文；向导会话仅在内存持有凭据，确认后按既有机制加密落盘，取消即丢弃；全程不写入日志或错误信息。

## Assumptions/假设

- 向导覆盖全部渠道类型（飞书为主场景），而非仅飞书——一致性是合理默认；飞书分步体验（P1）先行验收。
- 既有命令行标志方式完整保留作为非交互/脚本路径，二者产出等价（宪法原则 III：API 兼容性）。
- 渠道名称为可选字段，缺省使用"渠道类型 + 时间后缀"生成默认名。
- 向导运行环境为用户本机交互式终端；编辑已有渠道配置复用同一向导（编辑入口）为自然的后续演进，不阻塞本特性。
- 字段级校验规则沿用既有配置校验（格式/前缀/完整性），不新增对外部服务的实时验证（联通性验证仍由"测试发送"承担）。

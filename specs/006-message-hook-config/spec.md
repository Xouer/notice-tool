# Feature Specification/功能规格: Cross-Platform Message Hook Configuration/跨平台消息钩子配置

**Feature Branch**: `006-message-hook-config`

**Created**: 2026-11-08

**Status**: Draft

**Input**: User description: "端到端，发送消息配置钩子的信息，要具备linux,macos,window系统对应的配置钩子默认配置钩子的模板，例如在window模板里，要有记录各种平台编程agent的默认配置，并且要具有已启动，不启动的属性"

## User Scenarios & Testing/用户场景与测试

### User Story 1/用户故事 1 - View Cross-Platform Default Templates/查看跨平台默认模板 (Priority: P1)

作为使用本地 AI 编程智能体的开发者，我希望按当前操作系统查看内置的钩子默认配置模板，并在同一模板中查看 CodeBuddy、Claude Code、Codex CLI 的默认配置及其“已启动/不启动”状态，以便无需自行研究各产品配置方式即可完成接入准备。

**Why this priority/优先级理由**: 完整、可理解的默认模板是端到端接入的起点，直接消除用户不知道“在哪里配置、配置什么、是否生效”的障碍。

**Independent Test/独立测试**: 分别选择 Linux、macOS、Windows，检查每个系统均展示三类智能体的独立默认模板、配置内容和状态；无需启用模板或发送消息即可验证。

**Acceptance Scenarios/验收场景**:

1. **Given** 用户选择 Windows 模板分类，**When** 查看默认钩子配置，**Then** 能看到 CodeBuddy、Claude Code、Codex CLI 各自的默认配置、适用任务结束事件和“已启动/不启动”状态。
2. **Given** 用户分别选择 Linux 与 macOS 模板分类，**When** 查看默认钩子配置，**Then** 每个系统同样包含上述三类智能体的独立默认配置，且内容适用于所选系统。
3. **Given** 用户首次使用且从未启用任何模板，**When** 查看模板列表，**Then** 所有模板均显示“不启动”，目标智能体的既有配置未被改动。
4. **Given** 用户切换操作系统分类或智能体分类，**When** 返回先前查看的模板，**Then** 该模板的内容与状态保持准确，不因浏览操作发生变化。

---

### User Story 2/用户故事 2 - Enable a Hook and Receive Notifications/启用钩子并接收通知 (Priority: P1)

作为已配置通知渠道的开发者，我希望从默认模板启用指定智能体的钩子，并在该智能体的单轮问答或多步骤任务实际结束后自动收到消息，以便用一次当前对话验证从模板、钩子到消息送达的端到端链路。

**Why this priority/优先级理由**: 这是功能的核心价值；仅展示模板而不能形成停止通知，无法解决用户的实际问题。

**Independent Test/独立测试**: 在任一受支持系统上启用一个智能体模板，分别运行一次单轮问答和一次多步骤任务至实际 Stop，验证已启用通知渠道各收到一轮包含来源与结果的通知，同时模板显示“已启动”。

**Acceptance Scenarios/验收场景**:

1. **Given** 目标智能体模板为“不启动”且至少一个通知渠道已启用，**When** 用户确认启用该模板，**Then** 模板状态变为“已启动”，目标智能体的任务结束钩子具备向 NoticeTool 上报所需的信息。
2. **Given** 模板已启动且 NoticeTool 与通知渠道可用，**When** 目标智能体的单轮问答或多步骤任务成功、失败或被中断并触发 Stop，**Then** 用户收到一轮与实际结果一致的通知。
3. **Given** 用户已启用某一智能体模板，**When** 操作同一操作系统下的其他智能体模板，**Then** 已启用模板的内容与状态不受影响。
4. **Given** 启用过程中目标配置不可写或内容无效，**When** 启用失败，**Then** 用户看到可理解的失败原因，模板仍显示“不启动”，目标智能体原有配置保持可用。
5. **Given** 同一稳定 Stop 事件被重复接收，**When** 通知流程完成，**Then** 沿用事件键去重仅产生一轮通知；同一会话不同 Stop 不合并。

### User Story 3/用户故事 3 - Disable and Manage Hook Templates/停用并管理钩子模板 (Priority: P2)

作为需要调整或暂停自动通知的开发者，我希望随时将指定模板从“已启动”切换为“不启动”，并在修改默认内容或遇到既有配置冲突时得到明确提示，以便安全地控制每个智能体的通知来源。

**Why this priority/优先级理由**: 可控的启停与冲突处理让用户敢于采用默认模板，并避免通知失控或破坏已有智能体配置。

**Independent Test/独立测试**: 启用一个模板后将其停用，再运行一个任务，验证该模板不再触发通知且其他模板不受影响；另行模拟配置冲突，确认未经确认不会覆盖既有内容。

**Acceptance Scenarios/验收场景**:

1. **Given** 某模板显示“已启动”，**When** 用户确认停用，**Then** 状态变为“不启动”，后续任务结束不再通过该模板触发通知。
2. **Given** 多个模板均已启动，**When** 用户停用其中一个，**Then** 其余模板继续按各自状态工作。
3. **Given** 目标智能体已有用户自定义钩子或相关配置，**When** 用户启用默认模板，**Then** 系统明确展示冲突并要求确认，未经确认不覆盖或删除既有内容。
4. **Given** 用户重复启用已启动模板或重复停用不启动模板，**When** 操作完成，**Then** 状态保持不变，不产生重复钩子或重复通知。
5. **Given** 默认模板随产品版本更新，**When** 用户查看已采用过的模板，**Then** 用户已设置的启停状态与已确认的自定义内容不会被静默重置。

---

### Edge Cases/边界情况

- 当前系统与所选模板系统不一致时，必须明确标识适用范围，不得把其他系统的配置误报为已在当前系统启动。
- 目标智能体未安装、配置位置不存在或无写入权限时，启用应失败并给出排查指引，不得伪造“已启动”状态。
- 既有配置损坏或包含无法识别的内容时，不得静默覆盖；用户需能取消操作并保留原文件。
- 模板已启动但 NoticeTool 未运行、通知渠道未启用或网络不可用时，配置状态仍如实反映模板启停状态，同时通过既有历史与错误提示说明通知未送达。
- 智能体进程未运行不等于模板“不启动”；模板状态只表示钩子配置是否启用，不表示进程健康状态。
- 智能体升级后不再支持原默认配置时，必须标识配置失效并提供更新指引，不得继续显示端到端通知可用。
- 同一智能体存在多个配置范围或既有同类钩子时，必须避免重复注册和重复通知。
- 默认模板或状态信息包含本机用户名、目录等信息时，展示、日志与导出均不得泄露通知渠道凭据或其他敏感内容。

## Requirements/需求

### Functional Requirements/功能需求

- **FR-001 系统模板覆盖**: 系统 MUST 内置 Linux、macOS、Windows 三类默认钩子配置模板，并允许用户按操作系统查看。
- **FR-002 智能体模板覆盖**: 每类操作系统模板 MUST 分别包含 CodeBuddy、Claude Code、Codex CLI 的独立默认配置，共计九种操作系统与智能体组合。
- **FR-003 模板信息完整性**: 每个默认模板 MUST 展示适用系统、目标智能体、任务结束触发范围、完成钩子配置所需的信息以及当前启停状态，使用户无需阅读源码即可理解用途。
- **FR-004 双状态属性**: 每个模板 MUST 具有“已启动”和“不启动”两种持久状态；状态表示该钩子配置是否启用，不表示智能体或 NoticeTool 进程是否正在运行。
- **FR-005 安全默认值**: 所有内置模板初始 MUST 为“不启动”；浏览、查看或升级模板不得自动修改目标智能体配置。
- **FR-006 启用钩子**: 用户 MUST 能针对单一操作系统与智能体组合启用默认模板；启用成功后状态变为“已启动”，并形成从智能体任务结束到 NoticeTool 接收事件的有效钩子配置。
- **FR-007 端到端通知**: 已启动模板捕获实际 Stop（单轮问答或多步骤任务，成功、失败或中断）后，MUST 复用事件身份处理、去重、消息模板和已启用渠道完成通知。
- **FR-008 独立启停**: 用户 MUST 能将单一模板从“已启动”停用为“不启动”；任一模板启停不得改变其他智能体模板、通知渠道或无关配置。
- **FR-009 状态持久化**: 模板启停状态 MUST 在工具重启后保持，且展示状态必须与目标配置的实际可用性一致；验证失败时不得显示为可用。
- **FR-010 幂等操作**: 重复启用或停用同一模板 MUST 保持单一有效配置与正确状态，不得生成重复钩子。
- **FR-011 既有配置保护**: 启用模板前 MUST 检查目标位置的既有配置；发现冲突或无法识别的内容时必须说明影响并取得用户确认，未经确认不得覆盖，失败时不得留下部分写入。
- **FR-012 结果反馈**: 启用、停用和验证操作 MUST 给出明确的成功或失败结果；失败信息应包含用户可执行的排查方向，且不得包含凭据或完整敏感路径。
- **FR-013 配置适用性**: 系统 MUST 防止用户将不适用于当前操作系统的模板误报为已启动，并在目标智能体未安装或默认配置不再受支持时明确标识。
- **FR-014 默认模板演进**: 产品更新内置默认模板时 MUST 保留用户已设置的启停状态与自定义内容；需要变更既有接入时必须先提示用户。
- **FR-015 可观测性**: 系统 MUST 让用户区分“模板未启动”“钩子配置失效”“事件未到达”“通知发送失败”四类情况，以便定位端到端链路中断位置。

### Key Entities/关键实体

- **钩子配置模板/Hook Configuration Template**: 面向一种操作系统与一种智能体的默认接入定义，包含适用系统、目标智能体、任务结束触发范围、配置内容和版本。
- **模板实例/Template Instance**: 用户从默认模板采用的一份独立配置，关联目标智能体，具有“已启动/不启动”状态、用户自定义内容和最近验证结果。
- **钩子配置结果/Hook Configuration Result**: 一次启用、停用或验证的结果，包含操作状态、失败原因分类与时间，不包含敏感凭据。
- **任务结束事件/Task Completion Event**: 复用既有事件实体，记录来源智能体、任务标识、结果状态和结束时间，是模板启用后触发通知的输入。

## Success Criteria/成功标准

### Measurable Outcomes/可度量结果

- **SC-001**: Linux、macOS、Windows 与 CodeBuddy、Claude Code、Codex CLI 的九种组合模板覆盖率为 100%，每种组合均具备完整配置信息和两种启停状态。
- **SC-002**: 具备有效通知渠道的首次用户中，至少 90% 能在 5 分钟内按界面信息完成一个默认模板启用，并通过一次任务结束收到通知，无需查阅源码。
- **SC-003**: 对每个模板连续执行 20 次启用、重启查看、停用操作后，状态准确率为 100%，重复钩子数为 0，其他模板状态不受影响。
- **SC-004**: 在钩子与 NoticeTool 均可用的情况下，连续 20 个实际 Stop（含单轮与多步骤）均恰好形成 20 轮通知，通知结果状态准确率为 100%。
- **SC-005**: 在配置冲突、无权限、目标不存在和内容无效的测试场景中，100% 不出现未经确认的覆盖或半写入，且用户能看到明确失败原因。
- **SC-006**: 用户能在 2 分钟内通过状态与操作结果区分模板未启动、钩子失效、事件未到达和通知失败四类问题。
- **SC-007**: 安全抽查中，默认模板、状态展示、日志和错误信息泄露通知渠道凭据的事件数为 0。

## Security & Data Protection/安全与数据保护

- **数据类型**: 智能体本地钩子配置、配置位置、本机用户名可能出现的目录信息、模板启停状态、任务标识与结果概要；通知渠道凭据不属于默认模板内容。
- **访问主体**: 仅当前本机用户可以查看、启用、停用或验证模板；其他智能体和外部调用方不能批量修改模板状态或读取无关本地配置。
- **授权模型**: 采用最小权限原则，仅在用户明确操作后访问目标智能体所需配置范围；启用前展示写入目标与影响，冲突覆盖必须单独确认。
- **输入校验**: 默认模板内容、用户自定义内容与既有配置在写入前均须校验；拒绝不安全或无效的配置，操作失败时保持原有配置完整可用。
- **敏感信息保护**: 默认模板不得包含通知渠道凭据、访问令牌或个人消息内容；日志、错误信息与导出内容须对敏感路径和可能的用户标识进行脱敏。
- **失效与撤销**: 用户可随时将模板停用为“不启动”，撤销该模板产生的后续任务通知；停用不得删除通知历史或影响其他模板与渠道。
- **传输与留存**: 配置内容仅用于本机接入，不进行远端同步；任务事件与通知记录沿用既有本地留存和清除策略。

## Assumptions/假设

- 本功能首期覆盖 CodeBuddy、Claude Code、Codex CLI 三类智能体，与既有对话框通知功能的支持范围一致；新增其他智能体不在本次范围内。
- 三类智能体在三个桌面操作系统均可通过任务结束钩子或等价配置接入；具体产品能力差异在规划阶段核实，但不能减少九种组合的默认模板覆盖。
- “已启动/不启动”是配置启用状态，不是进程运行状态；默认全部为“不启动”，只有用户明确启用后才修改目标智能体配置。
- 端到端通知复用既有任务结束判定、跨来源去重、消息模板、通知渠道、历史记录和失败重试能力，本功能不重新定义这些规则。
- 用户已自行安装目标智能体，并具备修改其本地配置的权限；工具不代为安装智能体或获取通知渠道凭据。
- 本功能不包含智能体进程监控、跨设备模板同步、团队共享模板和通知渠道的新增类型。
- 默认模板覆盖实际 Stop 事件；单轮问答与多步骤任务均通知，同一稳定 Stop 事件跨触发源去重。
